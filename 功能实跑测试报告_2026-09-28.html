本轮修复的两个缺陷

① 员工离职/调岗联动 ReferenceError（我引入的作用域 Bug）
文件 server/routes/employees.js：const isDisabling 原声明在 if (hasEmployeeFields) {} 块内，而联动块在该块之外引用它，运行时抛 ReferenceError: isDisabling is not defined，导致离职/调岗 4 项全部 500。
修复：将 const isDisabling = String(status||'').includes('离职') || Number(status)===0; 提升到函数级作用域（块之前），块内仅保留权限校验 if (isDisabling && oldName) {...}。
② 请假提交 approver 为 undefined / NOT NULL 报错（预存脆弱性）
文件 server/routes/attendance.js：POST /leave-applications 当请求体无 approver 时，INSERT 绑定 undefined（mysql2 报错）→ 改为 null 后又撞上 leave_applications.approver 列的 NOT NULL 约束（ER_BAD_NULL_ERROR），均返回 500。
修复：（a）在校验阶段新增业务规则——缺审批人时返回干净的 400「请指定审批人」，不再 500；（b）INSERT 与通知/日志统一使用校验后非空的 approver。前端一向传审批人，因此为健壮性加固而非功能 Bug。
