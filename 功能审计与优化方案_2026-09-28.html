二、作废按钮问题（已修复）

现象

资产管理 → 盘点页签，对"进行中"的盘点单点「作废」，界面无任何反应。

根因（两层）

  • ① 前端错误被静默吞掉（直接原因，已修）： AssetManagementView.vue 中 voidInv 与 completeInv 的 catch 分支是 if (e !== 'cancel') console.error(e) —— 当请求抛异常（如后端返回 404/500）时只往控制台打日志、不弹任何提示，用户自然觉得"点了没反应"。而同页的保存/打开/新建都正确弹了错误提示，唯独这两个没有。
  • ② 部署机后端尚未包含该路由（根本触发条件）： 作废接口 PUT /api/asset-inventories/:id/void 是本地 commit 2530438 才新增的，位于本机工作树；但部署机 E:\qygl\qygl 由 Jenkins git reset --hard origin/main 拉取，这些提交尚未 push + 部署，因此运行中的 3005 后端无此路由 → 返回 404 → 被 ① 吞掉。

已做的修复

  • 已修改 AssetManagementView.vue：voidInv / completeInv 的 catch 在异常时除打印外，额外 ElMessage.error('作废/完成失败，请检查网络或后端是否已更新…')，确保任何失败都可见，杜绝"假死"。
  • 后端路由本身正确（路径、方法、仅"进行中"可作废、改状态为"已作废"并写操作日志均已就位），无需改后端代码。

仍需你这边做

⚠️ 把本地 16 个未推送 commit 推到 qygl-repo/main 并打标签 v1.2.51 → 等待 Jenkins 部署完成 → 在部署机 pm2 restart qygl 加载新后端。之后作废按钮即可正常生效，且即使后端异常也会给出红色提示而非无反应。

四、确认的问题清单

① 员工管理「导入Excel」按钮 → 404（确定 bug，高优）

证据：前端 EmployeeManagementView.vue:1861 调用 fetch('/api/employees/import', {method:'POST'})；后端 server/routes/employees.js 仅有 /employees/export、/employees/directory、/employees/:id/kick，无 /employees/import 路由。点击导入永远失败（前端会弹"导入失败，请检查文件格式"，但功能实质不可用）。

影响：批量录入员工无法使用。

修复方向：在 employees.js 补 POST /employees/import（解析 XLSX + 批量写入 + 与导出字段对齐）；或复用通用上传解析。需方案确认后实施。

② 审批中心「办公用品」标签错位（高优，UX 误导）

证据：OAWorkflowView.vue:147 渲染的 OfficeSuppliesPanel，实际调用 getProjects 且分发类型 type='project'，列展示 projectName / projectType（协同事项名称/协作类型）——它显示的是"协同事项/项目申请"，并非办公用品库存。真正的 /api/office-supplies 后端完整，但仅通过 /office-supplies 路由可访问，侧边栏没有该菜单。

影响：用户以为"办公用品"tab 是办公用品管理，实则是项目协同；同时真正的办公用品页在导航里找不到。

修复方向（二选一，待你定）：

  • A：把该 tab 标签改为「协同事项 / 项目协同」（如实反映 project_applications）；并在侧边栏补一个「办公用品」菜单指向 /office-supplies 独立页。
  • B：让该 tab 真正对接 /api/office-supplies（领用/库存），并把项目协同并入「审批中心·项目」或单独的协同菜单。

③ 路由重复挂载导致"遮蔽"（中优，维护风险，非功能断裂）

证据：server.js 中 workflowRouter(先挂) 与 projectApplicationsRouter / businessTripsRouter(后挂) 都定义了 /api/projects 与 /api/business-trips 系列。后挂的同方法同路径路由被遮蔽。

关键澄清（已核实，非断裂）：被遮蔽的两份 handler 都操作同一张表（project_applications / business_trip_applications），所以列表/审批/撤回/删除等对同一份数据生效，功能可用。但存在两份实现、部分操作路径分散（如项目审批：列表走 workflow.js，审批 PUT 走 project-applications.js），属于代码冗余与潜在逻辑分歧。系统约定"改项目逻辑改 workflow.js"，建议后续择机合并去重。

④ 部分"辅助加载"静默吞异常（中优，体验隐患）

除已修的作废/完成外，仍存在少量 catch { /* ignore */ } 或仅 console.error 不提示的位置：ArticlePanel.vue 的下拉选项加载（员工/角色/分类）、OAWorkflowView 的"下发记录"加载。这些失败时用户只看到下拉空白/列表为空，不知原因。建议统一加 ElMessage 或至少空态提示。

⑤ 流程引擎端点为死代码（低优，待清理）

src/services/workflow.ts 中的 getProcessDefinitions / startProcessInstance / processTask / transferTask 调用 /api/process-definitions、/api/process-instances、/api/tasks/:id/process 等，全代码无任何调用方，后端也无对应路由。属历史流程引擎残留，不影响功能，建议清理以减少混淆。

五、后续优化方案（菜单功能升级建议）

以下为"现有功能还能怎么做得更好"的方案，按模块给出，标注优先级。请确认方向后我再逐项出详细改造方案与代码。

通用基建（建议优先，解决"点了没反应"类体验） 高

  • 统一错误提示中间件：前端封装一个 request 拦截器，任何非 2xx 响应统一弹红色 ElMessage（含 HTTP 状态码与后端 message），彻底消除各按钮"静默失败"。本次作废问题正是此类。
  • 统一 Loading / 空态 / 二次确认：危险操作（删除、作废、批量）统一加确认弹窗与 loading 态，避免重复点击。
  • 前端路由守卫联动权限：对无权限菜单不仅在侧边栏隐藏，访问直链时也拦截提示。

审批中心 / OA 中

  • 修正问题②的标签/导航错位（协同事项 vs 办公用品）。
  • 统一审批交互：当前 7 类申请（请假/报销/会议/招待/协同/出差/项目）的审批入口、入参结构不一致（有的 PUT 整单、有的 POST /approve、有的用 localStorage 的 approverId）。建议抽象为统一的"审批组件 + 统一后端 approve 接口"，减少维护分叉。
  • 问题③路由去重合并。
  • 审批列表支持"批量审批""按审批人筛选""超时提醒"。

资产管理（已基本完善，锦上添花） 中

  • 领用单 / 盘点单打印增强：当前盘点单已可打印，建议领用也生成带签字栏的纸质单；盘点差异自动生成"盘盈/盘亏"处理建议。
  • 折旧自动计算：按 usefulLifeYears + acquireDate 自动算月折旧与累计折旧，概览直接展示，减少手工填。
  • 闲置资产预警：长期闲置（如 >180 天）资产高亮，提示处置/调配。
  • 二维码：之前已改为"复制编号"；若后续要扫码，建议接入真实设备绑定而非仅跳详情。

员工管理 高

  • 修复导入 404（问题①）：补齐 POST /employees/import，提供导入模板下载，字段与导出一致。
  • 员工离职/部门调动时联动资产责任人、账号禁用。

销售 / 客户模块 低

  • 销售漏斗导入提供模板下载与字段校验回显（哪行哪列出错）。
  • 客户跟进记录支持提醒（跟进到期）、客户公海/私海分配规则。
  • 成交项目与月报联动（成交自动汇总进月报）。

资料中心 低

  • 文件/文章全文检索、版本历史与回滚。
  • 大文件断点续传、预览水印。

系统管理 / 运维 中

  • 备份管理：增加"恢复演练"一键校验 + 备份保留策略（按天/按周自动清理）。
  • 操作日志：增加"按操作人/时间区间"导出、关键操作（删资产/删员工）强提醒。
  • 菜单/权限管理已可视化，建议增加"权限变更审计"。
