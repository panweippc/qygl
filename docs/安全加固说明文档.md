# 智慧办公平台 安全加固说明文档

> 适用系统：宏友软件 OA 系统（Vue3 + Express + MySQL）
> 文档版本：v1.2
> 更新日期：2026-08-19
> 本文档汇总了系统历次安全加固的全部内容，并对比加固前后的区别。

---

## 一、加固总览

本次安全加固覆盖 **密码安全、会话安全、接口安全、文件安全、数据安全、运维安全、Nginx 部署安全** 等维度，共实施 **40+ 项**加固措施。核心验证脚本 `verify-security.js` 最终 **19 项全部通过**。

### 加固前后核心指标对比

| 指标 | 加固前 | 加固后 |
|------|--------|--------|
| 依赖高危漏洞（critical） | 1 个（mysql2 RCE） | **0 个** |
| 密码存储 | 明文（6 位弱密码） | **bcrypt 加密（强密码）** |
| 敏感信息查看 | 所有登录用户可看全量 | **按角色脱敏** |
| 错误信息泄露 | 接口返回 error.message | **生产环境统一脱敏** |
| 账号锁定 | 无 | **登录/改密限流** |

## 二、密码安全

| 编号 | 加固项 | 加固前 | 加固后 |
|------|--------|--------|--------|
| P1 | 密码存储 | 数据库存**明文**（如 `123456`） | **bcrypt 哈希**加密存储，9/9 账号无明文 |
| P2 | 密码复杂度 | 无校验，任意弱密码可设 | **≥10位 + 大小写 + 数字 + 特殊字符**，排除常见弱密码、禁止含用户名 |
| P3 | 初始密码 | 固定 `123456` | **自动生成唯一随机强密码**（14 位），打印日志；或管理员自定义 |
| P4 | 新员工账号 | 新增员工不建登录账号 | **不填密码自动建号 + 自动生成强密码**，弹窗返回给管理员 |
| P5 | 改密要求 | 仅需填新密码 | 必须**验证旧密码**，新密码禁与旧密码相同 |
| P6 | 密码强度提示 | 无 | 修改密码/重置密码页显示**实时强度条 + 检查清单** |

## 三、会话安全

| 编号 | 加固项 | 加固前 | 加固后 |
|------|--------|--------|--------|
| S1 | JWT 密钥 | 默认/弱密钥 | `.env` 配置**强随机密钥**，生产环境未配置则拒绝启动 |
| S2 | Token 篡改 | - | 签名验证，**伪造/篡改 token 一律 401** |
| S3 | 改密后旧会话 | 改密后旧 token 仍有效 | **密码指纹机制**，改密后所有旧 token 立即失效 |
| S4 | Token 自动刷新 | token 过期需重新登录 | **静默刷新**（后端 `/auth/refresh` + 前端拦截器），并发只刷新一次 |
| S5 | 单设备登录 | - | Socket 会话记录，避免多设备共用 |
| S6 | 登录记录 | 无 | 个人中心展示**最近登录记录**（时间/IP/成败），便于发现异常 |

## 四、接口安全

| 编号 | 加固项 | 加固前 | 加固后 |
|------|--------|--------|--------|
| A1 | 登录限流 | 无 | **IP 级 30次/15分钟** + **账号级 5次错误锁定15分钟** |
| A2 | 改密限流 | 无 | 改密接口 **10次/15分钟**，防暴力猜解旧密码 |
| A3 | 越权访问 | 部分接口无权限校验 | 管理接口加 `requireRole`，**无权限 403** |
| A4 | 审批身份 | 信任 body/URL 的 userId | **身份取自 token**，防伪造越权 |
| A5 | 请求体限制 | 无 | JSON/URL **限 10MB**，防 DoS |
| A6 | 安全响应头 | 无 | **helmet**：nosniff、SAMEORIGIN、Referrer-Policy 等 |
| A7 | 版本号隐藏 | 暴露 X-Powered-By | **已隐藏** Express 版本 |
| A8 | 错误信息脱敏 | 返回 `error.message`（含 SQL/表名） | **生产环境统一脱敏**为"服务器内部错误" |

## 五、文件与上传安全

| 编号 | 加固项 | 加固前 | 加固后 |
|------|--------|--------|--------|
| F1 | 上传文件名 | 用户原始名 | **随机 UUID**，防冲突/路径注入 |
| F2 | 上传类型校验 | 扩展名白名单 | 扩展名白名单 + **魔数校验**（写盘后校验，伪装文件删除） |

| F6 | 上传者身份 | 信任请求体 | **从 token 取**，防伪造 |
| F7 | 附件下载路径穿越 | - | **拦截 `..`、`/`、`\`**，仅允许纯文件名 |
| F8 | 附件下载鉴权 | - | **requireAuth 完整校验**（签名 + 密码指纹） |

## 七·五、Nginx 部署安全

| 编号 | 加固项 | 说明 |
|------|--------|------|
| N1 | 敏感路径屏蔽 | `.env`、`.git`、`*.sql`、`*.log`、`*.bak`、`node_modules` 等返回 **403** |
| N2 | 登录限流 | `/api/auth/login` 每 IP 每分钟 5 次，超限 **429**（与后端限流双层防护） |
| N3 | 通用 API 限流 | `/api/` 每 IP 每 5 秒 30 次 |
| N4 | 连接数限制 | 单 IP 最多 100 并发连接 |
| N5 | 安全响应头 | CSP、X-Frame-Options、X-Content-Type-Options、X-XSS-Protection、Referrer-Policy、Permissions-Policy（`security-headers.conf` 复用） |
| N6 | 隐藏版本号 | `server_tokens off` |
| N7 | 缓存策略 | `index.html` 不缓存（发版即时生效）；`assets` 长缓存 7 天 + immutable |
| N8 | 静态资源优化 | gzip、`tcp_nopush`/`tcp_nodelay`、`open_file_cache`、worker 调优 |
| N9 | JSON 访问日志 | 含 `request_time`/`upstream_response_time`，便于性能排查 |
| N10 | 错误页 | 502/503/504 自定义页面 |
| N11 | HTTP/2 说明 | 明文 h2c 与部分客户端不兼容，暂用 HTTP/1.1；**启用 HTTPS 后开启 HTTP/2** |

## 十一、验证方式

运行安全验证脚本（会触发登录锁定，运行后需重启后端清除）：

```bash
node verify-security.js
pm2 restart qygl-backend --update-env
```

19 项验证项包括：
1. JWT_SECRET 已配置且强度达标
2. 密码 bcrypt 加密（9/9 无明文）
3. 密码复杂度校验（弱密码拦截、强密码放行）
4. 无 token 访问被拒（401）
5. 伪造/篡改 token 被拒
6. 登录限流（连续错误触发 429 锁定）
7. 后端接口连通性

## 十三、v1.2 新增加固（2026-08-19）

### 13.1 菜单权限初始化修复

| 编号 | 加固项 | 加固前 | 加固后 |
|------|--------|--------|--------|
| M1 | `roleName` 列名错误 | server.js 使用 `WHERE roleName = ?` 查询角色，实际列名为 `name`，导致监控菜单权限无法分配 | **修正为 `WHERE name IN (?, ?)`**，管理员和总经理角色正确获取全部菜单权限 |
| M2 | 菜单数据不完整 | `menus` 表仅初始化 5 条记录（系统管理/角色管理/菜单管理/OA办公/系统监控），缺少操作日志、安全事件监控等 11 个菜单 | **补全全部 16 个侧边栏菜单**，覆盖办公管理、业务管理、系统设置三大模块 |
| M3 | 非管理员角色无权限 | 除系统管理员/总经理外，其他角色（普通员工/财务总监/技术部经理/销售部经理）`role_permissions` 表为空，登录后看不到任何菜单 | **为所有角色分配基础菜单权限**（OA办公/月报/工具入库/文件存储/知识库/消息中心） |
